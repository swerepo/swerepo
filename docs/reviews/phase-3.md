### Design notes worth checking

1. **Managed vs starter files** (ADR-6c3d point 2). Only files SWERepo will keep current are recorded. PROGRESS, CHANGELOG, CONTRIBUTING and the README are meant to be edited, and recording them would make `check` report `~` for every edit.
2. **The plan builds the new `.swerepo.toml` in memory** and compares it with the old one, so "Nothing to do" is exact: a second run writes nothing, `.swerepo.toml` included (proposed rule `inv_1002d669`).
3. **Never replacing a file** is enforced at write time too: `open(..., "x")` for creation, and a re-read before appending a block. A file or block that appears between plan and apply stops the run (proposed rule `inv_8314036c`, critical).
4. **The ADR README's fingerprint leaves out the generated index.** Otherwise every new ADR would make it "changed by you". `check` and `init` share `blocks.file_fingerprint`.
5. **Values for managed templates are recorded and reused.** A later run renders with the recorded values, so a file stays `current` until its template version changes, even if, say, the Makefile gains a `test` target. Changing recorded values is `update`'s job (Phase 6).
6. **Two near-misses caught before review:**
   - (a) macOS's case-insensitive file system made a template folder `docs/readme` answer an older test's lookup of `docs/README`; I renamed the template to `docs/project-readme` rather than touch the test.
   - (b) a test string with a newline escape right before `@AGENTS.md` reads as a one-letter address in the `.md` domain to the locked privacy rule (the `.md` domain again, as in Phase 1), which would have blocked the commit; I changed the test's string, not the rule.
7. **Mutation checks.**
   - **`init` tests:** replacing existing files (`"w"` for `"x"`), ignoring edits, writing the state every run, and dropping a file's text when adding the block are each caught.
   - **Rule tests:** caught by both proposed rules, plus a dry run that applies. One mutation wasn't caught, and that's expected: skipping the "block changed" check alone changes nothing a test can see, because init never rewrites a recorded block.

### Known gaps and deliberate omissions

- **`update`** (merging newer templates into managed files) is Phase 6. Until then `init` reports `outdated` and leaves the file.
- **No license is asked for or written**, and **existing READMEs get no sections**: both changes to the spec (ADR-6c3d point 8).
- **`swerepo threads`** doesn't exist yet. The agents block's rule 7 doesn't name it until its template version (Phase 5).
- **`--mode` and `--projects`** belong to the `github` (Phase 5) and `ci` (Phase 4) components and aren't flags of this `init` yet.
- **Interactive questions** need a terminal on both stdin and stdout; tests drive them through a seam (`cli._interactive`).
- **The progress entry name** is `YYYYMMDD-swerepo-init.md`. A second `init` with changes on the same day keeps the first entry.

### Reviewer: findings

#### P3-F01 · blocker · `swerepo/cli.py:86`
**Problem:** In `cli.check` (`swerepo/cli.py:85-88`), `if skipped: components = [c for c in (components or COMPONENTS) if c not in skipped]` passes the resulting list as `only=components` to `run_check`. When `--only` was not given (`components is None`), `components or COMPONENTS` expands to **all 8 `COMPONENTS`** instead of subtracting from `chosen_components(state, detection)` (`swerepo/check.py:683`), forcing optional (`openspec`, `release`) and unchosen components on. In addition, when `--only ""` (or `--only ","`) is combined with any `--no-<component>`, `components` is `[]` (falsy), so `components or COMPONENTS` turns `[]` into `COMPONENTS` and bypasses `run_check`'s empty-`--only` `UsageError` (exit 2). (`tests/test_init.py:293-300` tested `--no-*` on `init` only, never on `check`.)
**Why it matters (scenario):**
1. After `swerepo init --yes` records `components = ["docs", "agents"]` in `.swerepo.toml`, `swerepo check` exits `0`, whereas `swerepo check --no-agents` unexpectedly checks `ci`, `security`, `github`, `seamspec`, `openspec`, and `release` and fails with `exit 1` (`15 missing, 0 changed by you, 0 outdated, 6 can't tell`) (reproduced).
2. On a repository without `.swerepo.toml` or `release.yml`, `swerepo check --no-openspec`—the exact example in `SWEREPO-SPEC.md` §5 principle 5 (`line 102`)—turns `release – not chosen` into `✗ release workflow missing (.github/workflows/release.yml)` and exits `1` (reproduced).
**Suggested fix:** Give `run_check` a `skip_components: tuple[str, ...] = ()` parameter (paralleling `make_plan(..., skip=skipped)`): validate `only` and `skip_components` separately, subtract `skip_components` from `only` when `only is not None` and from `chosen_components(state, detection)` when `only is None`, and add CLI tests for `check --no-openspec`, `check --no-agents` (with `.swerepo.toml`), and `check --only "" --no-docs`.

#### P3-F02 · blocker · `swerepo/blocks.py:40`
**Problem:** Four block/marker bugs in `swerepo/blocks.py` and `swerepo/init.py`:
1. **`replace_block_content` corrupts files containing Unicode line breaks (`swerepo/blocks.py:40-42`):** `find_block` (`swerepo/fingerprint.py:84`) splits lines only on `\r\n|\r|\n`, whereas `replace_block_content` slices `text.splitlines(keepends=True)`, which also splits on `\x0b`, `\x0c`, `\x1c`, `\x1d`, `\x1e`, `\x85`, `\u2028`, and `\u2029`. Any such character above `<!-- swerepo:adr-index:begin -->` shifts `lines` relative to `block.begin_line` / `block.end_line`, overwriting lines outside the markers and deleting `<!-- swerepo:adr-index:begin -->`.
2. **Uncaught `BlockError` in `file_fingerprint` (`swerepo/blocks.py:48`, called at `swerepo/check.py:657` and `swerepo/init.py:218`):** When `docs/adr/README.md` is recorded in `.swerepo.toml` (`docs/adr-readme@1`) and its `swerepo:adr-index` markers are broken, `find_block` raises `BlockError`, crashing both `swerepo check` and `swerepo init` (even `--dry-run`) with an unhandled traceback instead of reporting broken markers / keeping the file.
3. **Uncaught `BlockError` in `apply` (`swerepo/init.py:461`):** During `ADD_BLOCK`, `find_block(text, style=comment_style(action.path))` has no `except BlockError` handler, crashing `apply` with a traceback if malformed markers appeared in `AGENTS.md` after `make_plan`.
4. **CRLF trailing blank lines in `append_block` (`swerepo/blocks.py:31`):** `text.rstrip("\n") + "\n\n" + block` on `"# Rules\r\n\r\n"` strips only the final `\n`, leaving a bare `\r` (`"# Rules\r\n\r\n\n<!-- swerepo:begin -->"`—an extra blank line plus mixed `\r`).
**Why it matters (scenario):**
1. A contributor pastes text containing `U+2028` (Line Separator, common from macOS/rich-text copy-paste) into `docs/adr/README.md` above the ADR index and runs `swerepo adr index` → `replace_block_content` deletes `<!-- swerepo:adr-index:begin -->`, leaves the old row behind, and breaks `docs/adr/README.md` so subsequent runs fail with `BlockError` (reproduced).
2. Deleting `<!-- swerepo:adr-index:end -->` in a recorded `docs/adr/README.md` crashes both `swerepo check` and `swerepo init --dry-run` with a Python traceback instead of exiting cleanly with a broken-marker finding (reproduced).
**Suggested fix:**
1. Split `lines` in `replace_block_content` with `re.findall(r"[^\r\n]*(?:\r\n|\r|\n|$)", text)` (removing the trailing `""` match) so line numbers match `find_block` byte-for-byte, including with a leading UTF-8 BOM.
2. Catch `BlockError` in `file_fingerprint` (returning `fingerprint(text)` so a broken index hashes as changed while `check._adr_index` already emits the `✗` broken-marker finding, and mirror `_managed_block`'s broken-marker `KEEP` note in `init._managed_file`).
3. Catch `BlockError` in `init.apply` (`line 461`) as `InitError`, use `text.rstrip("\r\n")` in `append_block` (`blocks.py:31`), and add tests for `U+2028`, BOM, CRLF, and broken `adr-index` markers.

#### P3-F03 · blocker · `swerepo/init.py:449`
**Problem:** Three error-handling paths leak resolved home-folder paths or crash with raw tracebacks (plus unvalidated `--path` in `adr` and `progress`):
1. **`git init` failure leaks `str(root)` (`swerepo/init.py:447-449`):** `subprocess.run(["git", "init", "-q", str(root)], check=True, ...)` formats `InitError(f"git init failed: {error}")`. On `CalledProcessError`, `str(error)` includes the full command list containing `str(root)` (resolved on `line 443`, e.g. `/Users/me/project`), printing the user's home-folder path to stderr.
2. **Uncaught `OSError` and `UnicodeDecodeError` in `swerepo/adr.py` (`lines 46, 100, 104, 130, 144`):** `write_index` and `new_adr` read `README.md` / `TEMPLATE.md` with strict `encoding="utf-8"` and read/write files without catching `OSError` or `UnicodeDecodeError` (and `read_adr` at `line 46` doesn't catch `OSError`). Unreadable/read-only files or non-UTF-8 bytes crash `swerepo adr new` and `swerepo adr index` with Python tracebacks whose `PermissionError.filename` prints the resolved `/Users/me/...` path.
3. **Unvalidated `--path` and truncated folder names in `adr` and `progress` (`swerepo/cli.py:169-175, 214-219`, `swerepo/adr.py:99, 126`):** Unlike `check` and `init` (`UsageError(f"{root.name}: not a folder")`, exit 2), `swerepo progress --path /nonexistent` exits `0`, and `swerepo adr new "X" --path /nonexistent` exits `1` saying `adr/ doesn't exist` (`folder.name` prints only `"adr"` or `"decisions"` instead of `"docs/adr"` or `"docs/decisions"`).
**Why it matters (scenario):**
1. `git init` fails inside `/Users/me/project` (for example `.git` is an invalid file or permissions block creation) → `swerepo init --yes` prints `/Users/me/project` to stderr, breaking SWERepo's own no-home-path standard (`SWEREPO-SPEC.md` §6.1 / `ADR-20261120-fc5a`) (reproduced).
2. `docs/adr/` is read-only or `docs/adr/README.md` contains a non-UTF-8 byte → `swerepo adr new` / `swerepo adr index` dumps a raw traceback containing `/Users/me/...` instead of exiting `1` cleanly via `_fail` (reproduced).
**Suggested fix:**
1. Run `git init` with `check=False` in `init.apply` (reporting `exit status {done.returncode}` without `str(root)`) and format `OSError` with `error.strerror or type(error).__name__` (matching `line 468` and `state._reason`).
2. Catch `(OSError, UnicodeDecodeError)` in `read_adr`, `write_index`, and `new_adr` and raise `AdrError` using repo-relative paths and `error.strerror or type(error).__name__`.
3. Validate `root.is_dir()` (exit 2) in `adr` and `progress`, and display the repo-relative ADR folder path rather than `folder.name` in `adr.py:99, 126`.

#### P3-F04 · should-fix · `swerepo/init.py:388`
**Problem:** Four existing-repository and subfolder cases where `swerepo init` succeeds cleanly and `swerepo check --only docs,agents` immediately fails (or sets up the wrong folder), contradicting `ADR-20261121-6c3d` Consequences (`line 47`):
1. **`_progress_entry` skipped when only `.swerepo.toml` changes (`swerepo/init.py:388-390, 405`):** `make_plan` checks `any(a.changes for a in plan.actions)` on `line 388` *before* `_new_state` appends `WRITE_STATE` (`.swerepo.toml`) on `line 390`. In an existing repository that already has `README.md`, `docs/adr/{README,TEMPLATE}.md`, `docs/PROGRESS.md`, `CHANGELOG.md`, and `CONTRIBUTING.md` (all `KEEP`), `_progress_entry` never runs—leaving `line 405`'s fallback `"recorded the components in \`.swerepo.toml\`"` dead code, leaving the PR that adds `.swerepo.toml` without a progress entry, and leaving `docs/progress/` missing when the repository had none yet.
2. **Pre-existing `docs/adr/README.md` without index markers (`swerepo/init.py:216-217, 265-268` vs `swerepo/check.py:220-225`):** `_adr_dir` sets `adopted = False` whenever `docs/adr` is used, even when `docs/adr/0001-choice.md` and a hand-written `docs/adr/README.md` already existed before SWERepo. `init` prints `keep docs/adr/README.md (yours: SWERepo didn't write it)` with no warning, and `swerepo check --only docs` immediately exits `1` with `✗ docs/adr/README.md has no generated ADR index` (whereas `SWEREPO-SPEC.md` §6.5 `line 197` states an existing ADR folder's index is generated only if the person agrees).
3. **Running `init` inside a subfolder of a git repository (`swerepo/init.py:362`):** `make_plan` stops on `not detection.git.is_work_tree and detection.git.nested_repos`, but **not** when `detection.git.is_work_tree and not detection.git.is_toplevel`, contrary to `SWEREPO-SPEC.md` §11 (`line 441`, repository-level `docs` and `agents` live once at the root).
4. **`CHANGELOG.md` and `GEMINI.md` mismatches between `init` and `check` (`swerepo/init.py:300` vs `swerepo/check.py:28`, and `swerepo/init.py:240-242` vs `swerepo/check.py:308`):** `init.py:300` matches `r"^## \[Unreleased\]"` as a prefix (no warning on `## [Unreleased] - draft`) while `check._UNRELEASED` anchors `$` (`✗ CHANGELOG.md has no [Unreleased] section`). Conversely, `check.py:308` accepts any `GEMINI.md` containing `"AGENTS.md"`, while `init.py:240` checks only `line.strip() == "@AGENTS.md"` and appends a redundant block to a `GEMINI.md` that already links `[AGENTS.md](AGENTS.md)`.
**Why it matters (scenario):**
1. An established repository with existing docs but no `docs/progress/` runs `swerepo init --only docs --yes` → writes `.swerepo.toml` only → `swerepo check --only docs` exits `1` (`✗ docs/progress/ missing`, `Next: swerepo init --only docs`), and re-running `swerepo init --only docs` prints `Nothing to do.`—an unbreakable loop (reproduced).
2. An MADR repository with `docs/adr/0001-choice.md` and its own `docs/adr/README.md` runs `swerepo init --only docs,agents --yes` → `swerepo check --only docs,agents` exits `1` on `docs.adr-index` (reproduced).

### Reviewer: new findings

#### P3-F10 · blocker · `swerepo/blocks.py:50`
**Problem:** The rewritten `append_block` (`swerepo/blocks.py:50-51`) inspects trailing line breaks with:
`ending = re.search(r"(?:\r\n|\r|\n)*\Z", text)`
Because `(?:\r\n|\r|\n)*` can match each `"\r\n"` either as one `"\r\n"` branch or as `"\r"` followed by `"\n"`, whenever `text` contains a run of `n` consecutive `"\r\n"` line breaks *before* non-newline text later in the file, `re.search` fails `\Z` and backtracks through all $2^n$ splits (`O(2^n)` catastrophic ReDoS).
**Why it matters (scenario):** An existing CRLF `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` (or `.gitignore` / `CODEOWNERS` in Phase 4–5) has a run of blank CRLF lines in the middle of the file (`"\r\n" * n + "x\r\n"`): timed on Python 3.14, `n = 18` takes `0.08s`, `n = 20` takes `0.32s`, `n = 22` takes `1.28s` (exact $2^n$ doubling per blank line), and `n = 30` hangs `swerepo init` for over 15 minutes (reproduced).
**Suggested fix:** Slice trailing CR/LF characters directly without regex search or backtracking:
```python
ending = text[len(text.rstrip("\r\n")) :]
breaks = len(re.findall(r"\r\n|\r|\n", ending))
```
`text.rstrip("\r\n")` runs in C in linear time from the end of `text`, and `re.findall(r"\r\n|\r|\n", ending)` scans `ending` left-to-right with zero backtracking. Add `"\r\n" * 40 + "# End\r\n"` to `TestSeamSpecReviewOfInv8314036c.test_the_persons_text_is_kept_exactly_trailing_blank_lines_too` (`inv_8314036c` itself needs no change).
